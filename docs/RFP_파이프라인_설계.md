# 📑 RFP 발주 → 접수 → 분석 → 선정 파이프라인 · 딜 룸(VDR) 설계 (2026-11-28)

> 라이브: https://rnjswnsdh-lab.github.io/Jk-asset--map/ · 저장소 `rnjswnsdh-lab/Jk-asset--map`
> 서버: `docs/Rfp.gs` (Apps Script). **아직 배포 전이면 앱은 자동으로 💾 로컬 저장 모드**로 동작합니다.

## 0. 한 줄 구조

**딜 1건 = RFP 1건 + VDR(딜 룸) 1개 + 제출 폴더 1개.** 운영자(NAI·운용사)는 `🧾 자문사 딜` 보드에서
딜을 만들고, 참여자(자문사·투자자·금융기관)는 승인 코드로 **자기 딜 룸**에 들어옵니다.

```
🧾 자문사 딜 보드(첫 화면)
   └ 딜 카드 → 🏢 딜 룸(VDR)  ─ 자료(CA 게이트) · RFP 원문 · 내 제출물 · 일정 · 문의
                 ├ 📁 제출 폴더   ─ 초안 → 배포 → 접수 → 분석 → 담당자 검토 → 외부 보고 → 선정
                 └ 📈 자문 수행   ─ 착수 → 자료 인계 → TM/IM → 마케팅 → 입찰 → 협상 → 종결
💰 매칭 마켓 ─ 대출·금융(공급/수요) · PM/FM/보험(공급/수요) · 📋 용역 진행
```

## 1. 화면 모드

| 모드 | 누가 | 첫 화면 | 보이는 것 |
| --- | --- | --- | --- |
| 운영자 | NAI 관리자 · 내부 CM · 운용사 담당자 | `🧾 자문사 딜` 보드(전체 딜) | 전체 딜·평가표·굿/숏리스트·CA 대장·열람 이력·자료 등급·진위 판정 |
| 참여자 | 자문사 · 투자자 · 금융기관(승인 코드) | `🏢 내 딜 룸`(자기 딜만) | 자기 RFP·자료(CA 후)·자기 제출물·일정·문의. 다른 참여자 제출물·평가표 비노출 |

- 기존 `🤝 자문사 포털` 탭은 **참여자 모드 진입점**으로 남겨 두고, 코드 세션이면 "딜 룸으로 이동" 카드만 보여 줍니다.
- 금융기관 등록·실체 진위확인 메뉴는 **운영자 전용**이라 참여자 화면에서 뺐습니다.

## 2. 상태 흐름 (제출 폴더)

`초안 → 배포 → 접수 → 분석 → 담당자 검토 → 외부 보고 → 선정` (+ 선정 후 `자문 수행` 트랙)

| 전이 | 조건(막히면 사유 표시) |
| --- | --- |
| 배포 | 초청 자문사 1명 이상 |
| 접수 | 제안서 1건 이상 |
| 분석 | 평가 초안 1건 이상 |
| 담당자 검토 | 모든 제출 제안서가 「검토 완료」 |
| 외부 보고 | 운용사 담당자 확인(승인/조건부 승인) 기록 |
| 선정 | 선정 자문사 확정 |

모든 전이는 `history`(누가·언제·무엇을)에 남고, 이전 단계로 되돌리기도 기록됩니다.

## 3. CA 수기 절차 (전자서명 없음)

`CA 양식 다운로드 → 내부 결재 요청 → 결재 완료 → 날인본 등록 → 자문사 발송 → 서명본 회수(CA 접수) → 열람 권한 개방`

- 딜별 **원 양식 연결**: `📁 제출 폴더 → CA 양식 연결`(발주처가 준 docx/pdf). 없으면 임시 양식(자리 표시).
- 결재 승인 + 날인본 등록 전에는 **발송 단계로 못 넘어갑니다.**
- 발송은 기록만(자동 메일 발송 없음).
- 서명본 접수는 **참여자별**로 기록: 회사·담당자·서명일·적용 딜·파일·버전·상태(CA 미제출/CA 접수/반려).
- **전자서명·외부 서명 API 연동은 범위 밖** — 화면에 "추후 시스템 연동 검토(Phase 2)"로만 표기.

## 4. 자료 등급과 열람 판정 (한 곳에서 제어)

`rfpcore.js materialAccess()` — 포털·딜 룸·RFP·서버가 같은 규칙을 씁니다.

| 등급 | 기본 대상 | CA 미제출 | CA 접수 |
| --- | --- | --- | --- |
| 기본 개방 | IM·티저 / 렌트롤 / OPEX | 목록만(이름·존재) | 열람·다운로드 |
| 요청 시 개방 | 기타 자료(감정평가·도면·인허가·계약·실사) | 목록만 | **요청 → 담당자 승인** 후 그 참여자만 |
| 비공개 | 지정 자료 | 목록에도 안 보임(서버가 본문·메타 제외) | 동일 |

- 자료마다 버전·배포일·업로드자·열람자 수·다운로드 허용/차단을 기록합니다(교체 시 이전 버전 보관).
- 열람·다운로드 이력은 참여자별로 `rfp_access`에 남습니다.
- 기존 자산의 `im_url`/`im_label`(IM 보유분)은 VDR에 "자산 링크 보유"로 재사용하고, 없으면 **미보유**로 표기합니다.

## 5. 접수·분석·선정

- **접수 현황판**: 제출/미제출/마감 임박(D-3)/지연, CA 접수 수, 요구서류 충족 n/m, 제출 시각·버전·파일 수.
- **요구서류 충족**: 제안서·CA/서약서·신청서·실적표를 첨부 파일명·본문과 대조.
- **분석(플랫폼 초안)**: 평가항목 7축(실적·물건/시장 이해·매각전략·예상가격·매수의향자·조직/인력·보수, 가중치 합 100)에
  제출값·첨부를 대조해 점수·근거·미흡·의견 초안 생성. **"플랫폼이 만든 초안 · 확정 판단 아님"** 배너 표시.
  사람이 점수·의견을 수정하고 「검토 완료」 처리.
- **엑셀 리포트**: 요약 / 평가표 / 항목별 의견 / 제출 현황 / 선정 5시트, 출처·기준일 표기.
- **외부 보고**: 인쇄/PDF·Word·검토 요청 문안. 운용사 담당자 확인(승인/조건부/보류+의견)을 기록.
- **선정**: 순위·총점·사유와 함께 확정 → `selection`·`rfp` 상태·제출물 상태(선정/미선정) 동시 반영.

평가항목 배점은 실물 RFP 5건 모두 비공개(내부 기준)였으므로 **참여자 문서에는 항목명만**, 운영자 화면·출력에는 가중치를 표시합니다.

## 6. 투자자 흐름 — LOI / LOC / 자금조달 계획서 · 롱/굿/숏리스트

- 제출물 체크리스트(복수 선택): **① LOI ② LOC ③ 자금조달 계획서(S&U)**. 조합 자동 표기(LOI만 / LOI+LOC / LOI+자금계획 / LOI+LOC+자금계획).
- 딜별 **필수 제출물 지정** → 미충족은 보완요청 상태.
- 양식은 각각 다운로드 → 작성·서명 → 업로드(버전·시각·담당자 기록). LOC 「수용」은 **기관 인증완료**만 통과.
- **롱리스트**(제출자 자동 편입) → **굿리스트** → **숏리스트**: 판정(통과/보류/제외)·사유 코드·메모·평가자·일자 이력, 되돌리기 가능.
- 리스트 평가 항목(가격·조건·자금확보·실사계획·경험, 합 100)은 딜별 수정. 점수는 플랫폼 초안 → 담당자 판단.
- 굿/숏리스트·평가표는 운영자 전용, 투자자는 자기 상태만.

## 7. 금융 연결 (자문사 포털과 분리)

- **공급**: 금융기관이 딜에 "대출 가능·상신 금액·금리·LTV·트랑슈·만기" 조건 제시.
- **수요**: 투자자가 에쿼티·금액·금리 범위로 요청 → NAI가 기관 풀에서 매칭해 전달.
- 매칭 화면에서 요청↔제안을 조건으로 붙이고 상태(게시/검토/매칭/진행/종료)·이력 기록.
- 수수료는 **「수수료 협의」**로만 표기(금액·수취 주체 미정).
- **실체 진위확인(제도권 조회·사업자/등기 대조·도메인/콜백)은 운영자 전용.** 참여자는 자기 인증 상태만.
- 기존 `lenders`(금융기관 등록·인증)·`lois`(대출신청·금융주선 접수)·FI 풀 데이터를 재사용합니다.

## 10. 서버 (Apps Script) — 배포 절차

1. 편집기에서 `Rfp.gs` 새 파일 추가 → `docs/Rfp.gs` 내용 붙여넣기.
2. `rfpAppSession_()` 의 `hubSession_`/`requireSession_` 을 실제 Hub.gs 세션 함수명으로 교체.
3. `Hub.gs`의 `doGet`/`doPost`에 두 줄 추가:
   ```js
   if (type === 'rfp') return rfpGet_(token);
   if (/^rfp_/.test(body.action)) return rfpPost_(body, token);
   ```
4. `rfpSetup()` 실행 → 탭 생성 확인.
5. 웹앱 **새 버전으로 배포**(기존 URL 유지).
6. 앱 `📑 RFP` → `↻` → 배지 `☁ 서버 동기화` 확인.
7. 확인: 자문사 코드 응답에 다른 자문사 제출물 없음 / CA 미제출 코드에 자료 본문 없음 / LOC 「수용」이 미인증 기관에서 거부됨.
