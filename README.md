# Open AI Asset Bridge

NAI Korea의 상업용 부동산 물건 DB(호텔 · 물류센터 · 오피스 · 데이터센터 · 화주·임차수요)와
투자자 풀(SI·화주 / FI)을 카카오맵·카드 목록 위에서 조회·검색·필터·수정하는 단일 페이지 웹앱입니다.
**로그인 후 첫 화면은 `🏠 홈`(딜 브릿지 대시보드)** 이고, 지도·SI/FI·밸류에이션은 상단 탭에서 이어집니다.

## 📑 RFP 발주 · 🤝 자문사 포털 (2026-11-27 신설)

자산운용사·리츠·매도인(의뢰인)이 물건을 맡길 때의 전 과정 — **렌트롤·오펙스·PM 리포트 정리 → RFP 발주 → 자문사 제안 → 비교·평가·선정 → 자료 인계(승인 코드) → CA·TM/IM·마케팅 리스트 → 입찰·매수자·금융기관 인증** — 을 앱 안에서 처리합니다.

| 탭 | 쓰는 사람 | 하는 일 | 파일 |
| --- | --- | --- | --- |
| **📑 RFP** | 의뢰인(관리자·내부 CM) | 물건 자료 업로드·정규화(A) → RFP 작성·배포(B) → 제출 현황(C) → 비교표·가중치 점수·선정(D) | `rfp.js` `rfpcore.js` |
| **🤝 자문사 포털** | 자문사·매수자·금융기관(승인 코드) · 관리자 | 제안서 작성·제출(C) · 승인 코드 자료 열람·다운로드 이력(E) · CA 관리·TM/IM·마케팅 리스트(E) · 입찰·매수자 제출·LOI/LOC 검증(F) | `portal.js` `rfpcore.js` |

### 기존 `🧾 자문사 딜` 과의 역할 구분

| 구분 | `🧾 자문사 딜` | `📑 RFP` · `🤝 자문사 포털` |
| --- | --- | --- |
| 목적 | 외부에서 **자문사 딜 참여 의향을 접수**해 단계별로 정리(접수 → 자격·실적 → NDA → 자문계약 → 진행 → 완료) | 의뢰인이 **물건 단위로 RFP를 발주**하고 제안을 비교·평가해 선정, 이후 자문사 실무(VDR·CA·입찰)까지 |
| 데이터 | `lois` 중 `request_type=자문사딜` | RFP 모듈 자체 저장(`rfp` 계열 탭 — 아래 데이터 모델) |
| 주체 | 접수자(외부) → NAI | 의뢰인(매도측) ↔ 자문사·매수자·금융기관 |
| 쓰는 시점 | 딜 참여 문의 단계 | 물건을 실제로 맡기고 자문사를 선정한 뒤 |

### 흐름

1. **물건 자료(A)** — 물건 상세가 아니라 `📑 RFP` 탭의 물건 목록에서 `＋ 물건 불러오기`로 물건 DB의 물건을 선택합니다.
   - **렌트롤 / 오펙스 / PM 월간 리포트 / 기타(도면·감정평가·등기)** 업로드. 업로드 원본은 그대로 보관하고, CSV·XLSX(또는 표 붙여넣기)를 표로 파싱해 **임차인 수·임대면적·공실률·월 임대료·평균 임대료/평·WALE**, **오펙스 합계·평당 단가**, **PM 월별 이력**을 화면에서 확인·수정합니다.
2. **RFP 작성·배포(B)** — `새 RFP`를 누르면 렌트롤·오펙스·PM 리포트에서 **물건 개요가 자동으로 채워진** 표준 양식(업무 범위·일정·제출 요구서류·평가 항목·NDA/CA 조건)이 만들어집니다. 물건별로 수정한 뒤 `🖨 인쇄/PDF` · `⬇ Word(.doc)`로 내보내고, **자문사 배부**에서 초청 자문사를 고르면 자문사별 **승인 코드**가 발급되며 배포 기록이 남습니다.
3. **자문사 제안(C)** — 자문사는 `🤝 자문사 포털`에서 승인 코드를 입력해 **자기 RFP만** 열람하고, 요구 서류를 작성·파일 업로드·제출합니다. 마감 전까지 수정하면 **버전이 올라갑니다(v2, v3…)**. 의뢰인은 `📑 RFP → 비교·평가`에서 **초청 대비 제출/미제출**을 한눈에 봅니다. 자문사끼리 서로의 제안서는 **데이터 조회 단계에서 제외**되어 화면에 내려가지 않습니다.
4. **비교·평가·선정(D)** — 항목별 비교표(수수료·예상 매각가/기간·실적·투자자 접근력·인력·일정·추가 서비스·첨부)와 **가중치 점수표**(항목 0~100점 × 가중치 → 총점·순위 자동, `자동 채점` 지원), 평가 메모, 최종 선정. 비교표 CSV·인쇄 출력.
5. **자문사 포털(E)** — 선정된 자문사가 승인 코드로 **자료를 인계**받아 열람·다운로드(모든 이력 기록), **CA 관리**(매수자별 요청·체결일·공개 자료 범위), **TM/IM 제작 연결**(기존 홈 `NAI_HOME.brief` 재사용), **마케팅 리스트**(FI·SI·화주 `investors` 풀에서 대상 추가 → 발송일·TM/IM 버전·반응 기록, CSV).
6. **입찰·매수자·금융기관(F)** — 입찰 공고와 참여 양식(요구 서류) 등록 → 매수자 법인정보 등록·인증 → **입찰서·증빙·LOI·LOC 업로드(버전 관리)** → 검토 상태(제출/검토중/보완요청/확인) → **금융기관 등록·인증** → 금융기관이 LOI/LOC를 **검증(누가·언제·어느 기관)** 하면 접수 현황표에 반영됩니다.

### 권한

| 진입 | 볼 수 있는 것 |
| --- | --- |
| **관리자·내부 CM** | `📑 RFP` 전체 + `🤝 자문사 포털` 전체(코드 발급·종료, 열람 이력) |
| **자문사 코드** | 초청받은 RFP, 자기 제안서(타 자문사 제안서·평가 점수는 조회 자체가 불가), 공개 범위 내 자료, 해당 RFP의 CA·마케팅·입찰 |
| **매수자 코드** | CA에 적힌 공개 범위의 자료, 자기 제출물 — 제안서·다른 매수자 정보는 받지 않음 |
| **금융기관 코드** | 자기에게 온 LOI/LOC 검증 건과 기관 정보 |
| **물류TF·외부 방문자** | `📑 RFP` 탭 숨김(서버 판정 필요). 자료는 승인 코드 없이는 열리지 않음 |

- 코드는 `ADV-XXXXXX`(자문사) · `BUY-XXXXXX`(매수자) · `FI-XXXXXX`(금융기관) 형태이며 만료일이 지나면 자동으로 막힙니다. 매수자 코드는 **CA 체결 후** 발급할 수 있습니다.

### 데이터 저장 · 서버 API

- **현재 동작**: Apps Script 에 `type=rfp` API 가 아직 없어 **브라우저 localStorage**(`nai-map:rfp:v1`)에 저장되고 화면에 `💾 로컬 저장` 배지가 표시됩니다. 다른 기기와 공유되지 않습니다.
- **서버가 붙으면**: `GET ?type=rfp` → `{ok:true, data:{rfps:[…], submissions:[…], …}}`, `POST {action:'rfp_save'|'rfp_delete', entity, item}` 로 자동 전환(`rfpcore.js` 의 `pullServer`·`pushServer`). 응답이 없으면 로컬로 폴백합니다.
- 시트에는 RFP 탭 18종(`rfp`, `rfp_docs`, `rfp_items`, `rfp_invites`, `rfp_submissions`, `rfp_scores`, `rfp_codes`, `rfp_access`, `rfp_ca`, `rfp_marketing`, `rfp_notices`, `rfp_buyers`, `rfp_bid_subs`, `rfp_lenders`, `rfp_loi_conf`, `rfp_advisors`, `rfp_sessions`, `rfp_works`)과 헤더를 **미리 만들어 두었습니다**(기존 탭은 그대로). Apps Script 코드는 아직 배포 전이라 현재는 로컬 모드입니다.
- Apps Script 코드(`Rfp.gs`)·연결 위치·권한 판정·배포 순서는 **`docs/RFP_서버_패치.md`** 에 정리했습니다(서버 배포는 담당자가 진행).
- 로컬 데이터는 `📑 RFP → 내보내기(JSON)`로 백업·이전할 수 있습니다.

## ⌨️ Enter 키 · 검색 동작 정리 (2026-11-27)

| 화면 | Enter 를 누르면 |
| --- | --- |
| 🗺️ 물건 지도 통합 검색 | 디바운스를 건너뛰고 **즉시 검색** → 결과가 모두 보이도록 **지도가 이동**하고, 결과가 1건이면 상세까지 열립니다. 결과 0건이면 안내 문구가 뜹니다 |
| 🏠 홈 🔍 물건검색 | 검색 실행 (기존과 동일) |
| 🤖 AI 매물 매칭 | 문장 조건으로 매칭 실행 (폼 제출) |
| 🏷️ NAI 매각 / 🔑 LM · 🏢 SI·화주·FI 풀 · 🛰️ 관리자 · 📥 접수 목록 | 필터 즉시 적용 (모바일에서는 키보드가 닫혀 결과가 보입니다) |
| 📋 딜·참여 등록 허브(TR·매입 등) · 기타 모달 입력 | **다음 입력칸으로 이동**, 마지막 칸에서는 확인 버튼에 초점만 이동 (자동 접수되지 않음) |
| 물건 등록·수정 폼 | 다음 입력칸으로 이동. 저장은 `저장` 버튼으로만 (Enter 로 동기화 데이터가 생기거나 덮어쓰이지 않도록) |
| 주소로 위치 찾기 | `검색` 버튼 실행 |
| 접속 게이트 · 외부 방문자 인증 | 브라우저 기본 폼 제출 = `접속` / `명함 인증하고 입장` |

- 한글 조합(IME) 중의 Enter 는 글자 확정용이라 검색을 실행하지 않습니다(`e.isComposing` / `keyCode 229`). 조합이 끝나면 즉시 반영됩니다.
- 화면별 예외는 `data-enter="search"`(그 화면이 직접 처리) · `data-enter="off"`(아무 것도 하지 않음) 속성으로 표시합니다. 공통 처리는 `app.js` 의 `bindEnterFallback()`.

## 동작 방식

1. 첫 화면에서 접속코드를 입력합니다.
2. 브라우저가 코드를 SHA-256으로 파생해 접근 토큰을 만들고, 그 토큰을 이 브라우저의
   `localStorage`에만 저장합니다. 코드·토큰의 평문은 소스에 없습니다.
3. 토큰이 유효하면 Google Apps Script 웹앱(비공개 Google 시트)에서 물건 목록과 권한(`role`)을
   받아 카카오맵 마커와 목록으로 렌더링합니다.
4. 관리자 권한에서 수정·추가·삭제하면 같은 API로 시트에 즉시 반영되고, 실패 시 브라우저
   대기열에 남겨 두었다가 다음 접속 때 다시 전송합니다.

  ③ 관심도·온도/확인 센터수/확장 권역/NAI 담당자 ④ 사례·메모·출처 네 구역으로 나뉩니다.

  **서버(Apps Script)가 이 액션과 권한을 허용해야 실제로 저장됩니다.** 거부되면 모달 안에 서버 응답과 함께

- 펀드 메타데이터는 시트 `case_info` / `notes` 규격을 그대로 파싱합니다:

### 저장 규격 (§DISC)

공시 값은 공개 저장소에 두지 않고, 비공개 시트 `assets` 의 각 행 `facts` 칸에만 저장합니다.

```jsonc
// facts 배열의 한 원소
{"label":"§DISC","value":"{\"k\":\"K-REITS\",\"s\":\"출처\",\"a\":\"기준일\",\"t\":\"제목\",\n  \"kv\":[[\"라벨\",\"값\"]],\"li\":[[\"텍스트\",\"URL\"]],\"u\":\"원문URL\",\"n\":\"비고\"}"}
```

`§DISC` 항목은 상세 패널의 공시 섹션으로만 렌더링되고 **`상세 스펙` 표에서는 제외**됩니다.

### 2) 📋 TR 임차의뢰 (`tr.js`)
