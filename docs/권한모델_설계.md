# 접근권한 모델 — 사람별 · 범위별 (2026-11-28)

> 이 문서는 `Jk-asset--map`(Open AI Asset Bridge)의 접근권한 설계입니다.
> 서버는 Google Apps Script(`Acl.gs` · `Admin.gs` · `Hub.gs` · `Code.gs`), 데이터는 비공개 시트입니다.
> **화면 숨김은 보조 수단**이고, 실제 강제는 서버가 합니다(Acl.gs).

## 1. 왜 바꾸나

기존 `admin_access`는 `VIEW`(열람만) / `EDIT`(열람+수정) 두 단계뿐이었고, 그마저도 **🗂️ NAI 행정(회의록) 탭 하나**에만 적용됐습니다. 나머지 탭 노출은 `admin / internal / logi / external` 역할 단위로만 갈렸습니다.

- 물류센터 TFT는 **공용 아이디** 하나로 들어와서, 화주사 담당자·연락처가 전부 보였습니다.
- 외부에 플랫폼·물건을 알리려고 링크를 보내도 **볼 범위를 정할 수 없었습니다**.

그래서 권한을 **탭·데이터 범위 단위**로 바꾸고, **사람마다** 지정합니다.

## 2. 역할과 범위

| 역할 | 누구 | 범위(탭 키) | 수정 | 비고 |
|---|---|---|---|---|
| `admin` | 준오님(관리자 접속코드) | 전체 | 전체 | 관리자 화면·세션·로그·주소록 포함 |
| `internal` | CM팀 접속코드 | 전체 **− (adminhq, admin)** | 컨택트·CRM·회의록(명단에 있을 때) | **종전과 동일**. 회의록은 자동 부여하지 않음 |
| `logi` | 공용 물류TF 접속코드(레거시) | `map`, `ship` + 섹터 `logistics` | 화주 컨택트만 | **콘택트는 등록자만** — 공용 계정은 'logi-shared'로 등록한 것만 보임 |
| `person` | 관리자가 지정한 개인(개인 접속코드) | 부여한 `scopes` | `can_edit=Y`일 때 | 공용 TFT → 개인 계정 전환의 결과물 |
| `guest` | 초대 링크를 받은 외부·내부 인원 | 부여한 `scopes` | 없음 | 만료일까지만, **횟수 제한 없음** |
| `external` | 리멤버 명함 인증 방문자 | `map, nai_sale, nai_lease, match, vdr, portal, valuation, finance, advise` | 없음 | **기존 제품 동작 그대로**(회귀 없음) |

## 3. 시트 스키마

### 3.1 `admin_access` (확장 · 하위호환)

기존 열: `id, name, org, email, access, status, granted_by, granted_at, revoked_by, revoked_at, note`
추가 열: `scopes, can_edit, expires_at, sector_scope, person_code_hash, code_issued_at, code_hint, last_login_at, updated_at`

| 열 | 값 | 설명 |
|---|---|---|
| `scopes` | `map,ship` 등 쉼표 구분 | 비어 있으면 **기존 행 = `adminhq`만**(예전 의미 그대로) |
| `can_edit` | `Y`/`N` | 부여 범위 안에서 저장 허용 |
| `expires_at` | ISO 날짜 | 지나면 서버가 토큰을 거부 |
| `sector_scope` | `logistics` 등 | `map` 범위의 섹터 제한 |
| `person_code_hash` | SHA-256(`nai-asset-map:` + 코드) | **평문 코드는 저장하지 않음** |
| `code_hint` | `****AB12` | 관리자 화면 표시용 |
| `access` | `VIEW`/`EDIT`/`SCOPED` | 예전 화면 호환. `EDIT`는 `can_edit=Y`로 승계 |

- 기존 `VIEW` 행 → `adminhq` 열람 (그대로 동작)
- 기존 `EDIT` 행 → `adminhq` 열람+수정 (그대로 동작)

### 3.2 `guest_invites` (신설)

`id, token, name, org, email, scopes, sector_scope, expires_at, status, created_by, created_at, revoked_by, revoked_at, note, last_view_at, view_count, days`

- `token` = `GUEST:<uuid>` — 링크 `…/?guest=<token>`로 들어오면 그 토큰이 곧 세션입니다.
- **열람 횟수 제한 없음.** 만료일까지만 유효하고, 범위 밖은 서버가 내려주지 않습니다.
- 접속·열람은 `access_logs`에 남고, `last_view_at`·`view_count`는 1분 단위로 갱신합니다.

### 3.3 `admin` (NAI 행정 — 자료 단위 공유)

추가 열: `share_scope`, `share_with`

| share_scope | 뜻 |
|---|---|
| `all` (또는 빈 값) | `adminhq` 범위를 받은 사람 모두 (기존 행 호환) |
| `restricted` | `share_with`에 적힌 이메일·권한 id만 |
| `admin` | 관리자만 |

### 3.4 `investors` (컨택트 등록자)

추가 열: `contact_owner` — 컨택트 포인트를 등록한 사람의 이메일(개인 계정) 또는 `logi-shared`(공용 TFT).

### 3.5 `system_flags` (신설)

`key, value, updated_at, updated_by, note` — `legacy_logi`(`on`/`off`), `guest_days_default`(기본 30일).

## 4. 서버 강제 지점

| 요청 | 강제 |
|---|---|
| `GET`(물건 목록, 기본) | `aclFilterAssets_` — 범위·섹터로 거른 뒤 내려줌. 범위 없으면 `[]` |
| `GET ?type=investors` | `aclInvestorDeny_`(풀 없으면 403) → `aclFilterInvestors_`(kind) → `aclMaskInvestors_`(콘택트) |
| `GET ?type=valuations` | `valuation` 범위 없으면 `403 forbidden` |
| `GET ?type=requests` / `type=crm` | `requests` / `crm` 범위 없으면 `403` |
| `GET ?type=vdr_rooms|vdr_docs|vdr_bids` | `vdr` 범위 없으면 `403` |
| `GET ?type=admin` | `adminhq` 없으면 `unauthorized`, 있으면 `aclHqFilter_`로 자료별 필터 |
| `GET ?type=admin_access|logs|sessions|new_contacts|partners` | 관리자만 |
| `POST action=investor_save` | 범위 밖 kind 거부(`scope_kind`), 게스트·외부 거부, **남의 콘택트는 보존** |
| `POST action=admin_save` | 관리자, 또는 `adminhq`+`can_edit`+그 자료가 공유된 경우만 |
| `POST action=admin_acl_save|admin_acl_revoke|acl_*` | 관리자만 |
| `whoami` | 개인 코드 해시·게스트 토큰·만료·해제를 매 요청 검사 |

## 5. 기본값과 정한 것

| 항목 | 정한 값 | 근거 |
|---|---|---|
| 관리자의 콘택트 포인트 전체 열람 | **허용** | 등록·정정·중복 제거를 관리자가 해야 함. 일반 권한자는 본인 등록분만 |
| 내부(CM) 콘택트 | **종전과 동일**(전체, 전화번호만 가림) | 기존 사용자 잠금 금지 |
| 게스트 범위 기본 | `map, nai_sale, nai_lease` | "물건 지도·NAI 매각·임대를 볼 수 있게" |
| 게스트 만료 기본 | **30일**(화면에서 변경) | 홍보 링크 용도. 만료만 두고 횟수 제한 없음 |
| 게스트 열람 기록 | 접속·물건 열람 로그 + `view_count` | 누가·언제·무엇을 봤는지 |
| 공용 물류TF | **지금은 열어 둠** — 관리자 화면에서 한 번에 닫고 되돌릴 수 있음 | 개인 계정 발급 전 잠금 방지 |
| 공용 물류TF의 콘택트 | 공용 계정으로 등록한 것만 표시 | 공용 계정 하나로 전체 연락처가 보이던 문제 해결 |
| 개인 계정의 물건 수정 | 관리자만(종전과 동일) | 데이터 사고 방지. `can_edit`는 컨택트·CRM·회의록에 적용 |
| 내부 초대자에게도 범위 제한 | **적용** — 링크를 받으면 그 사람도 `guest`로 들어옴 | 사내 인원도 "보낸 범위만" 보는 것이 일관적 |

## 6. 개인 접속코드 발급 흐름

1. 관리자: 🛰️ 관리자 → **🔐 사람별 권한 · 주소록** → [＋ 권한 부여]
2. 사내 주소록에서 사람을 고르고 범위 체크 → [권한 부여]
3. 목록에서 **[코드 발급]** → `NAI-XXXX-XXXX-XXXX` 표시(한 번만) → [📋 전달 문구 복사]
4. 본인은 앱 → [🔑 내부 접속] → 코드 입력. 브라우저에는 해시 토큰만 저장됩니다.

## 7. 아직 남은 것

- `rfp`·`portal`·`finance`·`advise`는 화면 데이터가 서버 RFP 모듈(`Rfp.gs`)에 붙는 시점에 서버 강제를 추가해야 합니다(현재는 화면 숨김 + `type=rfp` 미배포).
- 인원별 감사 리포트(누가 무엇을 며칠간 봤는지 요약)는 `access_logs` 원본만 있고 요약 화면은 없습니다.
