# 🏦 금융기관 실체 진위확인 절차 — 설계·운영·서버 연동 (2026-11-27)

> 위치: `🤝 자문사 포털` → `🏷️ 입찰·금융기관` → **④ 금융기관 등록·실체 진위확인**
> 코드: `portal.js` (화면·판정), `style.css` (`.lv-*`), 서버는 `docs/RFP_서버_패치.md` 참고

## 1. 무엇을 확인하는가

대출·금융 제출(LOI/**LOC**)에 참여하는 기관이 **실제 그 기관인지, 가짜인지**를
담당자가 확인하고 그 근거를 남기는 절차입니다. 확인 없이 "인증" 버튼 한 번으로
끝나던 기존 수동 인증을 대체합니다.

| 단계 | 확인 내용 | 확인 방법(관리자 수동) | 통과 조건 |
| --- | --- | --- | --- |
| ① 제도권 금융회사 여부 | 인허가·등록·신고된 금융회사인지 | 금감원 **파인 — 제도권 금융회사 조회** / **등록대부업체 통합조회** 결과 기록 | 결과 선택(제도권/비제도권/확인 불가) + 근거 |
| ② 실체 확인 | 법인 실체·대표자·개업일 | **국세청 사업자등록 진위확인**(홈택스·공공데이터) + **법인등기부등본** 파일 대조 | 진위 "일치" + 등기부 "증빙 일치" + 등기부 파일 첨부 + 번호 체크섬 정상 |
| ③ 담당자 신원 확인 | 그 사람이 그 기관 담당자인지 | 업무 이메일 도메인 대조 + **기관 대표번호 콜백 기록** | 이메일·직함 입력 + 콜백(누가·언제·통화 상대·확인 내용) 필수 |

**외부 API는 호출하지 않습니다.** 서비스키·권한이 없고, 공개 저장소에 키를 둘 수
없기 때문입니다. 관리자가 공식 사이트에서 조회한 결과를 화면에 기록하고, 앱은
그 기록으로만 인증완료/반려를 판정합니다. 연동 지점은 5절에 주석으로 남겼습니다.

## 2. 상태 흐름

```
미확인 ──(저장)──▶ 확인중 ──(3단계 통과)──▶ 인증완료 ──(12개월)──▶ 재확인(확인중)
                      │                                          
                      └──(불일치·사유)──▶ 반려 ──(수정 후 저장)──▶ 확인중
```

- **미확인** — 등록 직후(신고값만 접수).
- **확인중** — 일부 단계 기록. 저장할 때마다 담당자·시각이 갱신됩니다.
- **인증완료** — 인증자·인증일시·근거 링크·3단계 결과·다음 재확인일이 저장됩니다.
- **반려** — 사유가 대장 카드에 남고, 그 기관은 LOI/LOC 확인을 할 수 없습니다.
- **재확인** — `next_review_at`(인증일 + 12개월)이 지나면 `재확인 필요`로 표시되고
  LOI/LOC 확인이 잠깁니다. `재확인`을 누르면 상태가 확인중으로 바뀌고 기존 기록을
  불러와 다시 확인합니다(이력은 보존).

### 인증완료 차단 규칙(코드에 구현됨)

1. ②에서 국세청 결과 `불일치` 또는 등기부 `증빙 불일치` → **인증완료 불가, 반려 유도**
2. 신고값과 확인값(기관명·사업자번호·대표자)이 다르면 자동 점검에서 `bad` → 인증완료 불가
3. 사업자등록번호 체크섬 오류 → 인증완료 불가
4. 법인등기부등본 파일 미첨부 → 인증완료 불가
5. 담당자 업무 이메일이 무료 메일(gmail·naver 등) → 인증완료 불가
6. 기관 대표번호 콜백 기록(일시·상대·전화·확인 내용) 누락 → 인증완료 불가
7. ①의 "확인 불가"는 선택 가능하지만 사유 메모가 필요(인증 카드에 표시)

> 이메일 **도메인 불일치**는 경고로 표시하고 인증완료를 막지는 않습니다(지주·계열사
> 메일 등 정상 예외가 있어 담당자 판단). 무료 메일만 차단합니다.

## 4. LOI/LOC 검증과의 연결

`⑤ LOI/LOC 검증 이력`에서 확인을 기록할 때 `lenderGate()`가 아래를 검사합니다.

| 상태 | 결과 |
| --- | --- |
| `인증완료` + 재확인 기한 이내 | 기록 가능 |
| `미확인`·`확인중`·`반려` | 차단 — "실체 진위확인이 완료되지 않았습니다" |
| 구 방식 `인증`(수동 인증) | 차단 — 3단계 재확인 필요 |
| `인증완료`지만 `next_review_at` 경과 | 차단 — 재확인 후 처리 |

검증 기록(`loiconf`)에는 `lender_verified_at`·`lender_next_review`를 함께 남겨
"어느 시점의 인증 상태로 확인했는지" 추적할 수 있게 했습니다.
금융기관 코드 발급도 같은 게이트를 통과해야 합니다.

## 5. 서버 스키마·연동 지점 제안

### 5.1 시트

`rfp_lenders` 헤더를 아래로 확장(기존 행은 빈 값으로 유지):

```
id, name, dept, manager, email, phone, status, verified_at, updated_at, json,
biz_no, ceo, opened_at, org_tel, verified_by, verified_at2, next_review_at,
step1_result, step2_tax, step3_domain, reject_reason
```

> 시트 열은 사람이 보기·검색하기 위한 사본이고, 원본은 `json`입니다. `verified_at2`는
> 기존 `verified_at`과 충돌하지 않도록 둔 별칭이며, 실제로는 `json.verified_at`을 씁니다.

**감사 로그 전용 탭 `rfp_lender_checks`(권장, 19번째 탭)** — 여러 기기에서 동시에
작업하면 `json.history` 배열이 덮어써질 수 있어, 서버에서는 append-only 행으로
남기는 편이 안전합니다.

```
id, lender_id, lender_name, step(1|2|3|all), result, by, at, source_url, evidence, memo, json
```

| 이벤트 | step | result 예 |
| --- | --- | --- |
| 등록 | all | 미확인 |
| 단계 저장 | 1/2/3 | 기록 |
| 인증완료 | all | 인증완료 |
| 반려 | all | 반려 (+memo=사유) |
| 재확인 착수 | all | 확인중 |

`Rfp.gs`의 `rfpSave_`에 `lender_checks`를 추가하고, `rfpGet_` 응답에
`lenderChecks`를 포함하면 됩니다(엔티티 이름은 `rfpcore.js`의 `COLLECTIONS`에 추가).

### 5.2 외부 API 연동 지점(키 확보 후)

지금은 호출하지 않습니다. 붙일 때는 아래 두 곳만 바꾸면 됩니다.

1. **국세청 사업자등록 진위확인** — `portal.js` `findings()`의 `tax_result` 판정을
   자동 호출 결과로 채우기. `POST https://api.odcloud.kr/api/nts-businessman/v1/validate`
   (본문 `{businesses:[{b_no, start_dt, p_nm}]}`, `valid=01`이면 일치).
   키는 Apps Script 스크립트 속성에 두고, 프런트는 Apps Script 액션만 호출하도록 권장
   (공개 저장소에 키 노출 금지).
2. **금융위 금융회사기본정보** — `step1.result`를 `fncoNm` 조회 결과로 자동 채우기
   (`GET https://apis.data.go.kr/1160100/service/GetFscCorpInfoService/getFscCorpOutline`
   계열, `fncoNm`·`bzno`·`fncoRprNm`·`fncoEstbDt`를 `declared`와 대조).

자동 호출을 붙여도 **인증완료 판정은 담당자 확인(콜백) 기록이 있어야** 열리도록
그대로 두는 것을 권장합니다.

## 6. 개인정보·저장 주의

- 저장소는 **공개 GitHub Pages**입니다. 실제 기관명·사업자번호·담당자 연락처·등기부
  파일을 커밋하지 마세요. 화면 검증은 가상 데이터(`예시은행`, `000-00-00000`,
  `example-bank.co.kr`)로만 합니다.
- 앱 데이터는 브라우저 localStorage(로컬 모드) 또는 비공개 시트(서버 모드)에만
  저장됩니다. 등기부 원본은 민감정보이므로 서버 배포 시 Drive 권한을 매도측·자문사로
  제한하세요.
- 화면의 `이력`·콜백 메모는 **관리자에게만** 보입니다. 자문사는 진행 단계만, 금융기관
  본인은 자기 상태·재확인 일정만 봅니다.

## 7. 화면에서 확인하는 방법(검증 시나리오)

1. `🤝 자문사 포털` → `🏷️ 입찰·금융기관` → `＋ 금융기관 등록`으로 가상 기관 등록.
2. `🔎 실체 진위확인 대장` 카드에서 `진위확인`.
3. ① 제도권 = `제도권 금융회사`, 근거 URL 입력 → ② 국세청 `진위 확인(일치)`,
   등기부 `증빙 일치`, 등기부 파일 첨부 → ③ 공식 도메인·업무 이메일·대표번호 콜백 기록,
   결과 `확인` → `인증완료`. 카드가 `인증완료 3/3`, 재확인 `+12개월`로 바뀝니다.
4. 반려 시나리오: 다른 기관을 등록하고 ②에서 `불일치`를 고르거나 신고값과 다른
   대표자를 입력 → 자동 점검 `✕` → `반려 사유` 입력 후 `반려`. 카드에 사유가 남습니다.
5. `⑤ LOI/LOC 검증 이력`에서 미인증 기관을 고르면 기록이 차단되는지 확인합니다.
