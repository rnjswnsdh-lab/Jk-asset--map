# Open AI Asset Bridge (가칭)

NAI Korea의 상업용 부동산 물건 DB(호텔 · 물류센터 · 오피스 · 데이터센터 · 화주·임차수요)와
투자자 풀(SI·화주 / FI)을 카카오맵·카드 목록 위에서 조회·검색·필터·수정하는 단일 페이지 웹앱입니다.
**로그인 후 첫 화면은 `🏠 홈`(딜 브릿지 대시보드)** 이고, 지도·SI/FI·밸류에이션은 상단 탭에서 이어집니다.

## 🏠 홈 — 딜 브릿지 대시보드 (2026-11-23 추가)

로그인하면 지도가 아니라 **홈**이 먼저 열립니다. 한 화면에서 매각 물건·아티클·공지·검색·등록·의향서/대출·TM·IM 제작으로 이어집니다.

| 섹션 | 내용 | 데이터 |
| --- | --- | --- |
| **🔥 매각중인 물건** | 온비드 경·공매 **입찰 D-Day**(`D-Day` / `D-2` / `수의계약`, 마감 지난 건은 `마감`) 배지 + 최저입찰가, 일반 매각·검토 물건 하이라이트(가격 상위). 카드 클릭 → 지도 + 상세 패널 | `assets` |
| **⚡ 바로 하기** | 물건검색 · 물건등록(TM/IM/직접) · 인수·임차의향서 · 대출요청/조건제시 · TM 제작 · IM 제작 | — |
| **🔍 물건검색** | 키워드(건물명·주소·운용사·임차인) + 섹터 + 구분(일반/경공매) + 권역 + 가격대 → 결과 클릭 시 지도·상세로 이동 | `assets` |

### ➕ 물건등록 — TM / IM / 직접 3가지

| 권한 | 처리 |
| --- | --- |
| **관리자** | `assets`에 **즉시 반영**(`source: 웹 직접등록`, `status_group: 검토중`). 저장 후 목록·지도에 바로 나타납니다 |
| **내부용 · 외부 방문자** | `asset_proposals`에 **제안**으로 접수(권한·제안자·연락처 기록). 관리자가 접수 내역에서 **승인**하면 `assets`에 반영되고 상태가 `승인`으로 바뀝니다 |

### 📝 의향서 · 💰 대출요청/조건제시

- **인수·임차의향서** — 대상 물건(목록 선택 또는 직접 입력), 매입/임차, 희망 가격·임차면적·임대료·시기, 회사·성명·연락처·메모 → `lois`
- **대출요청 · 대출조건 제시** — 대상 물건, 구분(대출요청/대출조건 제시), 금액·LTV·금리·만기·트랑슈(선/중/후순위), 담당자 → `loans`
- 두 폼 모두 **모든 권한**에서 제출할 수 있고, 접수 내역 조회는 관리자만 가능합니다(제출자 연락처 보호).

### 📄 TM / 📘 IM 제작 연동

물건 상세 패널과 홈의 `TM 제작`·`IM 제작`에서 **NAI Korea 양식 브리프 미리보기**(표지 · Deal Overview · 위치/스펙 · 임차·수익 · 투자 포인트)가 열리고,
같은 순간 `doc_requests`에 **제작 요청(물건 ID·양식·요청자·일시)** 이 기록됩니다.
미리보기는 `🖨 인쇄 / PDF 저장`으로 그대로 PDF로 저장할 수 있고, 제출용 `.pptx`는 로컬 생성기로 만듭니다.

```bash
# 비공개 시트의 물건 ID로 TM·IM(.pptx + .pdf + 미리보기 PNG) 생성
python3 work_tm_im/generate_tm_im.py --asset-id <물건ID> --token "$NAI_TOKEN" --kind BOTH --preview
python3 work_tm_im/generate_tm_im.py --json <물건 JSON> --kind TM --preview
```

### 홈 API (Apps Script v6 · `Home.gs`)

- `GET ?type=articles|notices` — 전 권한(비공개 글·작성자 제외)
- `GET ?type=lois|loans|doc_requests|proposals` — 관리자 전용
- `POST {action:'submit_loi'|'submit_loan'}` · `{action:'request_doc', doc_type:'TM'|'IM'}` · `{action:'submit_asset', proposal:{…}}` — 전 권한(신원·권한은 세션에서 기록)
- `POST {action:'article_save'|'article_delete'|'notice_save'|'notice_delete'|'proposal_approve'|'submission_status'}` — 관리자 전용
**가칭 `Open AI Asset Bridge`**는 NAI Korea 물건 DB를 기반으로 만든 프로토타입입니다.
빌드 도구 없이 정적 파일만으로 동작하며, GitHub Pages에서 서빙됩니다.

- 배포 주소: <https://rnjswnsdh-lab.github.io/Jk-asset--map/>
- 접속은 **3단계 권한**입니다. 코드/인증이 없으면 물건 데이터는 1건도 로드되지 않습니다.
  - **관리자** — 조회 + 수정·추가·삭제 + 저장 + 메일 발송
  - **내부용** — 전체 조회(이메일 유지)만. 전화번호는 서버가 `비공개`로 가리고, 쓰기는 서버가 거부
  - **외부 방문자** — 리멤버 명함 인증(또는 신규 등록)으로 발급된 세션. 조회·시뮬레이션만 가능하고
    담당자 컨택포인트(이름·직책·이메일·전화)는 서버가 내려주지 않으며 메일 발송 바가 숨겨집니다

## 동작 방식

1. 첫 화면에서 접속코드를 입력합니다.
2. 브라우저가 코드를 SHA-256으로 파생해 접근 토큰을 만들고, 그 토큰을 이 브라우저의
   `localStorage`에만 저장합니다. 코드·토큰의 평문은 소스에 없습니다.
3. 토큰이 유효하면 Google Apps Script 웹앱(비공개 Google 시트)에서 물건 목록과 권한(`role`)을
   받아 카카오맵 마커와 목록으로 렌더링합니다.
4. 관리자 권한에서 수정·추가·삭제하면 같은 API로 시트에 즉시 반영되고, 실패 시 브라우저
   대기열에 남겨 두었다가 다음 접속 때 다시 전송합니다.

## 🤝 SI·화주 풀 / 🏦 FI 풀 탭 (2026-11-22 분리)

상단 4개 탭 **`🗺️ 물건 지도` | `🤝 SI·화주 풀` | `🏦 FI 풀` | `📊 밸류에이션`** 으로 화면을 전환합니다.
SI·화주 풀과 FI 풀은 **같은 `investors` 시트**를 읽되, 분류(`kind`) 범위만 나누어 보여 줍니다.

- 데이터: 비공개 시트 **`investors`** (Apps Script `type=investors`). 물건 DB(`assets`)와 분리되어 있습니다.
  v3 기준 **1,787건** — `office_si` 959 · `shipper` 166 · `blind_fund` 426 · `reit_foreign` 193 · `pension_lp` 43.
- **🤝 SI·화주 풀 (1,125건)** — `🏢 오피스 SI`(권역: CBD · GBD · YBD · 강남·서초·수서 · 판교·분당 · 서부·마곡·구로),
  `🚚 물류 화주`(권역: 수도권 동남 · 수도권 남부 · 수도권 서부 · 수도권 동부 · 충청 · 지방·전국 · 전국·미확인).
- **🏦 FI 풀 (662건)** — `💰 블라인드펀드`(247개사) · `🌐 리츠·해외투자사`(103개사) · `🏛 연기금·LP`(24개사).
  카드마다 **전략(Core / Core+ / Value-add / Opportunistic / Loan / 개발)** 배지와
  **펀드명 · LP · 규모·약정 · 드라이파우더 · 목표 IRR · 지역 가이드 · 만기**가 표시되고,
  `전략` 칩·`펀드 정보 있는 건만` 토글로 좁힐 수 있습니다. `🔎` 버튼은 펀드별 상세(투자 대상·만기 포함)를 엽니다.
- 공통: 검색(기업명·사례·펀드·담당자·이메일), `이메일 있는 건만`, 체크박스 다중 선택,
  하단 **메일 발송 바**(`📧 선택 대상 메일창 열기`(mailto BCC) / `📋 이메일 목록 복사` / `🤖 Jk 발송 요청문 복사`).
  메일 앱이 열릴 뿐, 앱이 직접 메일을 보내지 않습니다. 선택 상태는 탭별로 따로 유지됩니다.
- 관리자 코드에서만 `＋ 대상 추가` · `✏️` · `🗑`가 보이며, 저장·삭제는 같은 API로 `investors` 시트에 반영됩니다.
  읽기 전용 코드에서는 조회·검색·메일 준비만 됩니다.
- 펀드 메타데이터는 시트 `case_info` / `notes` 규격을 그대로 파싱합니다:
  `[펀드명] LP:… | 전략:… | 규모:… | 드라이파우더:… | 목표IRR:… | 지역:… | 만기:…`,
  `notes`의 `드라이파우더 합계 … · 목표IRR: … · 지역가이드: …`.

API 응답은 기존 규격을 그대로 두고 `type=investors` 파라미터(또는 POST body `type`)로 분기합니다.
`GET  …/exec?token=…` → 물건, `GET …/exec?type=investors&token=…` → SI·화주 풀.

## 📊 밸류에이션·민감도 탭 (2026-11-22 추가)

상단 **`📊 밸류에이션`** 탭. 물건의 렌트롤·OPEX·CAPEX를 입력으로 매입~매각 현금흐름을 계산합니다.
물건 상세 패널의 **`📊 수익성 시뮬레이션`** 버튼을 누르면 그 물건이 로드된 채로 이 탭으로 이동합니다.

- **프리셋 3종**
  - `종로플레이스 (오피스 기본)` — 실제 체결 렌트롤(2026.10.31)·OPEX(2025) 원문, 6대 시나리오 ② 에셋딜 단일 3,500억·10년
  - `종로플레이스 (9·10F 엣지DC 3,800억)` — 매입 3,800억 + CapEx 800억 = 총투자 4,600억, 순증 NOI +57.5억(2028~), 부채 3,103억
  - `김포고촌 KMTC 물류센터` — 하나대체86호 월간보고서(렌트롤 시트 3.2·P/L 시트 4) + NAI 제안서 조달·Exit 가정
- **입력**: 매입가 ↔ 이니셜 캡 연동, 매입·매각 부대비용, 엑시트 캡, 연 임대수입/평당 월 임대료·렌트프리·공실률·상승률,
  관리비·주차수입, OPEX, 기타비용, 초기/연간 CAPEX, 밸류애드 추가 NOI, 선순위·중순위 LTV와 **구간별 금리(1~2 / 3~5 / 6년차~)**, 승계 보증금.
- **산출**: 매입가·평당가, 총투자비, 에쿼티, Y1 NOI, Going-in Cap, Levered/Unlevered IRR, EM, 평균 CoC, Exit 매각가, 최저 DSCR + 연도별 현금흐름표.
- **민감도 2종**: ① 이니셜 캡 × 엑시트 캡(IRR/EM/매각가) ② 조달금리(전 구간 ±) × 엑시트 캡(IRR/CoC/EM).
  스텝 ±0.25/0.50%p·칸수 ±1~3, 기준 셀 하이라이트, 목표 IRR 이상 초록 강조.
- **저장**: 관리자 코드만 `💾 시트에 저장`(비공개 시트 `valuations`), 읽기 전용은 계산·민감도만.
  API: `GET …/exec?type=valuations&token=…`, `POST {action:'upsert'|'delete', type:'valuations', …}`.
- **데이터 구분**: 각 프리셋의 가정 목록에 `원문` / `가정` 배지를 달아, 원문에서 확인된 수치와 시장 가정치를 구분합니다.

- **Case A — 이미 명함을 교환한 분**: 이름·회사·전화번호를 입력하면 Apps Script가 비공개 시트

  일치하면 외부 전용 세션 토큰(`EXT:…`, 7일)을 발급하고 `access_logs`에 기록합니다.
- **Case B — 아직 친추 전인 분**: 권준오 상무(NAI Korea, 010-7731-4316)와 리멤버 명함 교환 안내 후
  이름·회사·직책·전화번호·이메일·관심 섹터·친추 완료 체크를 받아 `new_contacts`(신규 컨택포인트 DB)에
  즉시 저장하고 `access_logs`에 남긴 뒤 외부 토큰으로 바로 입장시킵니다(같은 이름·번호 재방문은 갱신).
- 외부 열람의 제한은 **서버(Apps Script)에서** 적용됩니다. 브라우저에서 숨기는 방식이 아니라
  `GET ?type=investors` 응답에서 `contact`·`title`·`email`·`phone`을 제거해 내려줍니다.

### API (v5)

- `POST {action:'auth_external', name, company, phone}` → `{ok, token:'EXT:…', name, company}`
- `POST {action:'register_external', name, company, title, phone, email, interest_sector, remember_checked}` → 외부 토큰
- `POST {action:'log_event', kind, detail}` → 탭 이동·물건 클릭·조회 기록(모든 권한)
- `GET ?type=logs|new_contacts|remember|sessions&token=…` → 관리자 전용 백오피스 조회

## 📋 공시·공공 데이터 (2026-11-23 추가)

물건 상세 패널에 **`📋 공시·공공 데이터`** 섹션을 추가했습니다. 공시 카드는 출처·기준일과 함께
표시되고, 각 카드에 원문(공시 사이트) 링크가 붙습니다. 배지 `📋 공시 N` 은 그 물건에 연동된
공시 카드 수이고, 목록 행의 `📋` 는 공시자료가 붙은 물건 표시입니다.

현재 연동 결과: **물건 1,853건 중 664건(35.8%)** — K-REITS 387 · 온비드 268 · DART 86 (2026-11-23 기준).

### 연동 소스 (모두 공개 공시 · 키 불필요)

| 소스 | 가져오는 값 | 기준 |
| --- | --- | --- |
| **K-REITS** `reits.molit.go.kr` | 리츠명·자산관리회사·리츠 유형·공시상 자산명·투자대상·**연면적·대지면적·완공일**·인가/등록일·상장일·**연환산배당률**·**자산총계·부채총계·자본총계·자본금**·최대주주 | 조회 시점 공개 공시 |
| **온비드** `onbid.co.kr` | 공매 상태·입찰기간·개찰일시·최저입찰가·감정가·입찰회차·공고일·물건번호 | 재동기화 시점 |
| **DART** `dart.fss.or.kr` | 해당 리츠·운용사의 부동산 관련 최근 공시 5건(보고서명·접수일·원문) | 조회 시점 |

- 물건↔리츠 매칭은 **지번(시군구·법정동·본번·부번) 완전일치**만 인정합니다. 추정 매칭은 하지 않습니다.
- 건축물대장·실거래가·개별공시지가·토지이용계획은 **공공데이터포털(data.go.kr) 서비스키 등록 후**
  자동 수집 대상입니다(현재 미연동 — 아래 '미연동 사유' 참고).

### 저장 규격 (§DISC)

공시 값은 공개 저장소에 두지 않고, 비공개 시트 `assets` 의 각 행 `facts` 칸에만 저장합니다.

```jsonc
// facts 배열의 한 원소
{"label":"§DISC","value":"{\"k\":\"K-REITS\",\"s\":\"출처\",\"a\":\"기준일\",\"t\":\"제목\",\n  \"kv\":[[\"라벨\",\"값\"]],\"li\":[[\"텍스트\",\"URL\"]],\"u\":\"원문URL\",\"n\":\"비고\"}"}
```

`§DISC` 항목은 상세 패널의 공시 섹션으로만 렌더링되고 **`상세 스펙` 표에서는 제외**됩니다.
재실행하면 해당 물건의 `§DISC` 항목만 교체됩니다(멱등).

### 파이프라인

`work_disclosure/sync_disclosures.py` — 수집 → 매칭 → 카드 생성 → 시트 upsert 를 한 번에 수행합니다.


## 보안 메모

- 이 저장소에는 **물건 데이터가 포함되어 있지 않습니다.** 데이터는 비공개 Google 시트에만 있습니다.
- 접속코드와 접근 토큰은 저장소에 커밋되지 않으며, 사용자가 화면에서 직접 입력합니다.
  Apps Script에는 코드의 **SHA-256 해시만** 두고, 외부 방문자 세션은 서버가 발급한 무작위 토큰입니다.
- `remember_contacts`·`new_contacts`·`access_logs`는 모두 비공개 시트이며 앱은 관리자/내부/외부 권한에 따라
  서버에서 필드를 지운 뒤 내려줍니다.
- 앱은 엣지(Edge)·크롬·사파리 최신 버전에서 동작합니다. 접속코드 파생에 Web Crypto를 쓰므로
  HTTPS(GitHub Pages) 또는 `localhost`에서만 접속이 가능합니다.
